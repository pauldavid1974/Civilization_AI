# Project brief / PRD — Civilization_AI

## Current milestone — 29 October 2026

The owner has now authorized a bounded original TypeScript/Node engine, SQLite persistence
and Phaser viewer: [The Living Valley — Prototype 0.1](docs/specs/living-valley-0.1.md).
Four inhabitants and deterministic test cognition form the first runnable slice; actual LLM
and advanced memory are pending. The governance-setup scope and proposed future milestones
below are retained as historical context, not a denial of this newer authorization.
No spending, provider calls, deployments, public access or governance changes are authorized.

## Problem / why

Explore whether autonomous AI inhabitants can live, learn, explore and create a shared history
with lasting consequences. Convincing dialogue alone does not establish a functioning society.
The experiment needs continuity, meaningful choices and observable causes.

## Goal / outcome

An open-source, persistent AI civilization where autonomous inhabitants live, learn, explore,
and create their own history. An indefinitely developing civilization is a research ambition,
not a promised capability or a condition for a useful small prototype.

## Users / context

Paul is the sole product/governance owner and initial observer/operator. Developers and AI
coding agents contribute through reviewed changes. Human or AI visitors and public spectators
are possible later users, each requiring a separate design and authorization.

## Scope

- **In the vision:** autonomous inhabitants, durable identity and experiences, evolving goals,
  relationships, exploration, experimentation and emergent social history in a graphical world.
- **First engineering direction:** start with a few inhabitants and prove continuity before
  expanding. Four adults and a small valley are review recommendations for the first slice.
- **Current deliverable:** establish governance and planning documents only.
- **Out of this setup:** simulation code, packages, model downloads, paid inference, deployment,
  visitor integrations, resident internet capability, streaming and generation mechanics.

## Requirements

- Inhabitants can initiate and reconsider goals; their lives are not fixed scripts.
- Choices and experiences have durable consequences beyond a single model response or session.
- Start small; population growth must follow measured performance and behavioral evidence.
- World days and nights run faster than real time. Interactions remain responsive in real time;
  exact clock, pause and inference-outage behavior need an approved implementation contract.
- Preserve the founding vision rather than requiring scripted elections, conflict or milestones.
- Make observation useful: show actions and evidence for important outcomes without confusing
  an observer's knowledge with what an inhabitant actually knows.

## Non-functional needs

- **Security / privacy:** source is public; credentials, personal records, private mind records
  and runtime state are not public repository content. Separate observer, inhabitant and future
  administrator/visitor privileges in an approved design before implementation.
- **Performance / limits:** benchmark useful decisions, latency, memory and fair opportunities
  before promising population or runtime scale. No spending is authorized by governance setup.
- **Platform:** browser viewer and a persistent backend are proposed. No runtime is installed
  and no hosting target or supported package version is selected by this PR.
- **Reliability:** proposed acceptance work includes restart continuity and genuine restore
  evidence; persistence and long-term autonomy must not be claimed from saved biographies alone.

## Constraints / decisions already made

- Public GitHub repository: https://github.com/pauldavid1974/Civilization_AI, default branch `main`.
- Original MIT license is unchanged, including intentional copyright holder `DraganDrop`.
- Use the established Repo Governance V3 single-owner configuration. Paul alone ratifies
  governance changes; agents propose them on branches and do not merge them.
- **Stack under consideration:** TypeScript/Node.js, SQLite, Phaser, replaceable inference through
  llama.cpp/Ollama or other adapters. These are architecture recommendations, not installed or
  finally approved dependencies. Pin and verify versions when implementation is authorized.
- Starting small and accelerated time are owner direction. A 10-minute day plus 10-minute
  night is a prior assistant suggestion, not a fixed owner-approved duration.

## Success criteria (how we'll know it works)

- **This setup:** faithful, traceable V3 controls; a coherent single-owner profile; meaningful
  governance checks; unchanged license; and a governance-only PR for Paul, left unmerged.
- **Future first slice, proposed:** an inhabitant's chosen plan survives restart; a witnessed
  experience changes a later action; an impossible action cannot mutate reality; closing the
  viewer does not stop the world. Agree exact pass/fail evidence in the implementation spec.
- **Research progress:** demonstrate causal continuity and useful behavioral memory, rather
  than merely fluent prose or entertaining outcomes. A quiet society can be a valid result.

## Risks / open questions

- Local inference capacity, operating cost, useful cognition cadence and safe population limits.
- Exact time ratio, slowdowns, pauses, downtime and inference-outage policy.
- History retention/reconstruction contract and a tested backup/restore destination and target.
- Who may inspect private thoughts and what a future public spectator may see.
- Material action semantics, personal knowledge boundaries and extensible physical systems.
- Original Astra analysis was not recovered; the available follow-up review is advisory and
  cannot stand in for missing owner approval. See `docs/decisions.md`.

## Milestones (proposed; no implementation authorization)

1. Approve governance, then a bounded first-slice spec and its unresolved owner decisions.
2. Benchmark inference and prove a small persistent world with a minimal browser inspector.
3. Validate restart, outage, viewer independence and restore before larger or prolonged trials.
4. Consider expansion, visitors, generations and public observation as separate later decisions.
